# 1.2.5 聊天执行边界审查与修复

审查基点：`abc3afda6c83199cc0b0ef51572526f3ac3f0587`，远程分支 `fix/1.2.5-chat-loop-catalog`。

## 修复范围

平台负责传递任务、协议、真实结果和资源预算。移除以关键词或回答措辞代替模型规划的规则，保留取消、超时、上下文保护和副作用重放保护。

| 原行为 | 修复后的行为 |
|---|---|
| 关键词识别领域后插入 system 指令、生成固定计划 | 保留用户原文与时间事实，使用中性进度事件 |
| narration/promise/list-only/explore 规则催促立即执行 | 不因提及命令、礼貌性承诺或查询次数而增加执行指令 |
| 正文/思考中的 JSON、XML、代码示例被扫描成操作 | 执行器只消费明确的工具调用事件 |
| 非原生模型依赖无边界 JSON 文本协议 | 适配器教授并验证完整的执行信封；不解析 fenced 示例或混合说明 |
| 工具后或裁剪前历史超过 18K 时关闭 thinking | 续轮、总结和恢复沿用配置 |
| 相同结果三轮硬断、失败两次后本轮永久封禁 | 使用明确的轮数、时间和 token 预算；允许状态验证和修复后重试 |
| vision/image_edit 同参复用、定时 agent 已成功调用永久去重 | 重新执行，保留新的观察；不把相同参数当成结果不可变的证据 |
| 参数前 100 字符用于判断调用相同 | 不截断参数；同一响应内仅以重复调用 ID 去除传输重复 |
| 同 ID skill 首次正文固定、搜索结果也升格为指南 | 更新实际指南；搜索和错误保留为普通结果 |
| 根据工具名/实体键合并结果、替换合法空 JSON | 保留观察顺序和业务输出 |
| 成功 stdout 追加跨域帮助、因输出提及错误词而判失败 | 保留 stdout，采用结构化状态、退出码和超时标记 |
| 前端 21 分钟硬断短于后端可配置任务时限 | 后端管理任务预算；前端继续检测断流和缺失终止事件 |

## 前端影响

页面聊天与悬浮面板共用 `useChatStream`。现有 Content、Thinking、ToolCallStart/End、Progress、IntermediateEnd、End、取消及恢复帧保持兼容。界面不依赖假定的意图/计划事件结束任务；没有调用时不会凭正文生成工具卡片。

修复图片正文在结束阶段重复发送，以及总结推理混入最终正文的问题。检查实时结果与保存历史一致，保留错误后缺失结束帧的恢复逻辑；心跳只证明连接仍在，不会解除错误期限。

取消和预算同时约束模型请求建立、流读取与工具调用。丢弃流会终止其后台 HTTP 任务，避免停止界面后还占用模型槽位。已完成工具的结果继续保留；中断副作用工具的结果按“未知”报告，不盲目重放。

## 兼容边界

- 内部 Rust `StreamChunk` 改为 `Result<StreamEvent, LlmError>`。自定义 runtime 需分别发送 Text、Thinking 和 ToolCalls；元组可通过 `.into()` 转成文本/思考事件。
- 非原生工具模型使用完整 `<neomind_tool_calls>[...]</neomind_tool_calls>` 响应，名称必须来自本次工具列表且参数为对象。普通 JSON、代码示例和未知工具名保持文本。
- 原 OpenAI 兼容端点的 XML 恢复仅在 `NEOMIND_LEGACY_TEXT_TOOL_CALLS=on` 时启用。该选项恢复文本解析兼容行为，原生调用应优先使用。
- HTTP/WS 消息格式、设置存储与旧历史字段不要求迁移。旧 `behavioral_guards` 字段保留源码兼容，已不再启用语义干预。

## 验证边界

审查先使用捕获模型请求、计数工具和内存状态复现 13 项问题；这些是确定性的代码回归检查，不是真实模型跑分。修复后还验证原生/文本协议、实际执行次数、结果与推理分流、取消和预算、以及前端完整流状态机。

本轮没有连接 T4 或重新跑 138 条真实模型评估。移除多项干预后需要固定提交、模型、采样、上下文与服务再做完整配对评估；单靠单元测试或此前分支的少量观测，不能宣称本轮模型质量已经全量验收。
