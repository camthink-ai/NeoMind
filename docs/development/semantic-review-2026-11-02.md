# NeoMind：独立语义验收

## 本批保留内容

Mac 仓库 `cead1801` 上新增 Python 设备证据提取、LLM 语义评审、校准样例和命令行入口。生产设备字段、Rust 回答逻辑及原命令/状态评分均未在本批修改。保留之前经验证的改动，不重新应用已撤回的提示头部、长提示或 `_diagnostic_evidence` 包装。

- `eval/lib/semantic_evidence.py`：从直接的 device get/history/list 调用提取实体、当前状态、指标、窗口、分页和失败信息。未知来源、错误实体和损坏输出不当作事实。
- `eval/lib/semantic_review.py`：LLM 逐行评审事实断言、明确标注的假设和建议。证据引用从代码生成的编号目录中选择，再由代码解析真实路径和值。引用正确不保证自然语言判断正确。
- `eval/semantic_review.py`：显式启用，分别输出 PASS / FAIL / ABSTAIN，保留评审输入、输出、配置和哈希，原评分只读。没有评审服务、输出不完整或引用无效均不能计作通过。
- `eval/lib/server.py` 与 `eval/run_eval.py`：从实际 WebSocket end 事件采集 `generation_complete`。缺少此字段的旧记录不补写成功；显式截断也弃权。
- `eval/semantic/README.md`：入口、退出码、凭据传入方式、证据边界和局限。

API key 经安全终端临时输入，没有写入文件、日志或仓库。内部网关声明的模型为 `glm-5.3-flash`；网关返回元数据不独立证明底层模型身份。

## 验证

云端和 Mac 新增语义相关 unittest 均为 23 项通过。原 hard_signal standalone 为 24/24，preflight 为 8/8，diff check 通过。本批没有 Rust 修改，未把上一批 3692 项 Rust 测试冒充本批重跑结果。

20 个本轮预设标注的校准样例（由实现者编写，尚无独立人工盲审）全部匹配：PASS 8、FAIL 7、ABSTAIN 5。该结果仅是当前校准集通过，不能推断真实场景评审准确率或安全性；仍需独立留出集和人工盲审。名为 prompt-injection 的旧样例仅验证过滤后的输入，不构成完整注入防护验收。

最初两轮自由生成 JSON 路径的评审在前 4 个样例中出现无效引用，均拒绝并保存停止原因。之后改为选择证据编号，校准才通过。不是容错修复错误引用后强行算通过。最终校准采用临时 4 并发调用包装器，独立审查每个样例；CLI 默认仍串行。全部结果按输入顺序保留，不用于耗时比较。

## 新的真实 Spark 记录

固定此前 Spark 模型和 runtime SHA、Mac Metal、32K 单槽、temperature 0.3 / top_p 0.75 / top_k 20；使用保留版本二进制。device-offline-no-data 与 device-update-name，中英各两轮，共 8 次。命令/状态硬评分 8/8，真实结束事件 8/8。此处没有候选行为修改，不构成 A/B 提升结果。

逐条阅读四条诊断，仍有 last_seen 推断刚断线、空窗口推断从未上报、当前 false/null 推断从未连接等问题。初次自动评审：2 FAIL、6 ABSTAIN。其中 4 个普通改名用例包含本评审器不支持的写入调用，按设计弃权；另 2 个诊断请求评审服务不可用。原始结果保留，没有把弃权计入通过。

仅对这 2 个服务不可用的原始回答安排一次独立重试，将请求时限由 120 秒设为 300 秒，不重新生成 Spark 回答，不替换初次结果。重试结论追加在本文末尾。

## 后续约束试验

优先验证“事实断言草稿 → 证据编号绑定 → 一次有界自检 → LLM 自然语言收尾”，先做离线对照，暂不接入生产。LLM 负责语义与表达，代码负责证据编号、实体、时间窗和预算边界；不要使用固定话术替换模型回复，也不要循环重试直到评分通过。

留出集必须包含当前离线/历史有数据、当前在线/历史为空、历史请求失败、分页未完、用户自述与平台观测不同、明确假设和建议、普通改名控制。保持 Spark 与同机推理配置不变，同时记录命令/状态和事实准确性；存在 PASS→FAIL、输出截断或弃权时独立报告。若有界自检仍无收益，停止堆叠提示，依据错误分布评估模型训练或能力边界。

## 最终复核结果

两条服务不可用记录的一次重试均为 FAIL，没有弃权。结合初次已完成的两条诊断评审，四个诊断回答全部存在无证据断言；首次结果仍为2 FAIL/6 ABSTAIN，不覆盖为新的全量评分。普通改名控制的硬状态仍为4/4，其语义结论超出当前只读设备评审器范围。

因此本批交付的是可复核的语义评审工具及基线证据，不能宣称 Spark 诊断准确率或全量 eval 分数提升。下一批应以这个失败基线对照有界事实自检，先离线验证再决定生产接入。最终代码检查通过，自建推理服务及本轮评审进程均退出，无提交、推送或发布。
