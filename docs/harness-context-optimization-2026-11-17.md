# Harness 上下文与 skill 优化交付（2026-11-17）

## 范围与结论

基于本地 1.3.0 的 CLI 收敛提交 18715a40，独立工作树实现、验证后合入 1.3.0 工作区。未提交、未推送、未部署。其它执行者的 MQTT、配网、前端 WIP 不属于本轮，也不计入验证结论。

这是可进行配对业务评测的实现候选，不是客户发布验收通过。没有运行模型生成，因此不能宣称任务成功率、循环率或延迟已改善。

用户授权覆盖 skill 工具代码、内置 skill 文本、对话中的 skill 加载与保留逻辑，以及其它 harness 优化。

## CLI 收敛复审

三个业务工具的注册与实现已经由前一提交移除。本轮没有恢复专用业务入口。历史工具名的读取/归因兼容路径不能据此一并删除。

发现并修复：
1. slim 系统提示词和 agent-management 仍引导使用已删除的 query_conclusion/run_now。统一为 agent latest-execution / invoke，并区分读旧结论与发起新执行。
2. CLI agent invoke 的 HTTP 等待已是 70 秒，服务端耐心窗口 60 秒，但生产 shell 配置仍 30 秒，流式调度外层默认 35 秒。现在 shell 默认 90 秒，外层由实际工具 execution_timeout 声明，shell 在自己的配置/请求超时之上留 5 秒清理时间。数值、字符串形式的 timeout 与自定义 ShellConfig 均走同一解析路径；上限仍 600 秒执行 + 5 秒清理。没有按 agent/device 命令文本增加特殊超时分支。
3. 保留未知结果不得盲目重试的账本/授权/交付语义；修改超时不是将 Executing 或 accepted 当成业务成功。

## 实现

### Skill 渐进加载

- 保留 15 个内置 ID、触发词、原有分类元数据以及用户自定义 skill 管理能力。
- 工具目录按接入、业务编排、包管理/开发、系统运维分组展示，降低查找负担。
- 默认 load 返回简明工作指南 + sections 目录。新增可选 section，按返回的准确章节标题取详细参考；支持 ASCII 大小写与两侧空白归一化。
- 未知/重复标题可见报错，并列出可用章节；错误 section 类型不静默退回概览。
- 详细资料保留在 <!-- SKILL_REFERENCE --> 后。没有该标记的既有自定义 skill 仍全文加载。
- pinned skill 默认注入概览；总 skill 预算不放宽。
- Chat 保留键由 skill ID 扩展为 ID + 已解析章节标题，概览与参考章节可同时保留，同一章节重读不重复占用。
- 原有新用户 turn 清理策略保留。多模态使用相同提取/保留方法。
- 验证 skill 探索守卫允许“概览 → 不同章节”，但仍阻断无进展的重复读取；没有把停环阈值放宽。

### 文本精简

- 系统提示词收敛为语言/身份、工具发现、任务执行、结果证据、记忆与时间。
- 清理已退出注册的业务工具指引；按需 --help、skill 和文件/网页工具各自职责保留。
- 明确错误传输与业务状态区别、未知写入先查询、执行中不重新 invoke、按操作确认、已接受与物理完成区别。
- 删除强制“下一步必须创建”的过度流程指令；只发现缺失或过期事实，复用当前会话中的已核实信息。
- rule 指南保留用户指定阈值，去掉“根据当前读数挑阈值”的误导；不再把配置外部通知渠道作为创建平台消息的统一前置条件。
- 首次 skill 不再整篇注入。完整参数/示例仍可按章节获取，不把减少文档行数当成目标。
- memory 仍按需读取；持久化保留用户显式要求或至少三次观察的条件。

### 其它通用改进

- 未在固定优先级表中的工具按名称排序，消除 HashMap 导致扩展工具尾部顺序随进程启动变化。
- shell 执行超时和调度超时由同一个工具声明衔接，避免硬编码两份默认值。
- 没有新增模型路由器、业务专用工具或一套平行执行状态机。

## 下一步最小配对业务验收

冻结两臂：A=18715a40 CLI-only 基线；B=本轮完整 patch。若后续基线移动，两臂必须共享除 harness 以外的同一业务代码、设备/消息/agent 夹具。
同模型权重/量化、llama.cpp build、chat template、上下文上限、采样参数、硬件、缓存冷热条件。每次重置业务状态并保留原始请求、工具结果、状态查询、终态和 prompt token 记录。
不要修改历史 138 用例/结果；新建 harness-context-v1 对比集，评分首先看业务结果，工具入口契约另列。

12 类任务，每类中文/英文、2 个固定种子：每臂 48 试，共 96 试：
1. 已有明确 ID 的设备查询：不先读无关 memory/skill，返回真实数据。
2. 指定设备命令与简单参数：下发次数正确，交付等级诚实。
3. 设备命令参数含空格/引号/中文：CLI 参数准确，不发明字段。
4. 参数错误后返回 schema：有针对性纠正，不重复同样错误。
5. 查询已有 agent 结论：不新增执行，结论含正确对象/新鲜度。
6. 请求 agent 新执行，服务端用可控夹具模拟 40–60 秒才返回：不得 30 秒中断；只执行一次。
7. 模拟等待结束仍执行中：使用原 execution_id 查询，不重新 invoke、不报告已完成。
8. 多轮改目标/改阈值：遵循最新用户修改，不复用错误对象或确认授权。
9. Rule 创建与解释：保留指定阈值/单位；缺数据时 unknown；不自行触发设备来验收。
10. Transform：概览 → 输入/schema 章节 → 测试 → 保存；失败输入/外部调用阻断不能被报告成验证成功。
11. 设备接入：同 topic 多身份、发现后批准；配置成功和真实数据到达分别判定。
12. Dashboard 或通知配置：概览后按需取参考；重载同一章节不涨预算；错误章节可恢复；完成配置后读回目标状态。

每试独立记录：
- 业务是否成功、目标对象是否正确、状态证据是否支撑最终回答。
- 未授权写入、重复执行、错误成功/物理完成宣称。
- CLI 参数错误次数、无进展重复调用、skill 加载次数和重复次数。
- 请求输入 tokens、总生成 tokens、工具耗时、端到端时延；冷/热缓存分开比较。
- 超时/用户取消单独分类，不能全部记成业务 Failed。

预先固定通过规则：
- 未授权写入、错误目标写入、未知结果后重复执行、虚报完成：任一出现即阻塞。
- 旧自定义 skill、pinned、概览/章节、中文/英文、带图路径均无契约回归。
- B 的业务成功试数不低于 A；新增失败逐例解释并修复，不用总均分掩盖关键回归。
- 固定夹具系统+工具预算至少降低 15%（本轮静态测量达到）；实际完整任务 token 与延迟单独报告，不能由静态节省推断。
- 无进展循环和错误 CLI 次数不得上升；少数慢案例列原始轨迹。
- 48 试/臂仅作工程筛查，不宣称统计显著；若存在分歧，增加相应任务重复而非改评分标准。
